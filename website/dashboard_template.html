A plain-language guide to this experiment

Can a fake look real enough?

Honey Encryption is designed to make a wrong password produce a believable decoy instead of an obvious error. This project tests that idea with made-up cards and accounts, then improves the decoys when patterns give them away.

Explore the resultsTry the interactive simulator

What did we learn?

The first set of decoys had telltale patterns. After those patterns were corrected, the test classifier had a much harder time telling a real item from a decoy.

The score is a research test, not a guarantee of real-world security. Every example in this experiment is synthetic.

Honey Encryption in three steps

A simple way to think about what happens when an attacker tries a stolen encrypted file.

1 · The file is stolen

The attacker has encrypted data and tries a password from a list of guesses.

2 · A wrong guess still opens a decoy

Instead of an error, Honey Encryption can produce a plausible-looking fake. The attacker may not know which result is genuine.

3 · Patterns can give fakes away

If the decoys look different from genuine data, an attacker can learn those differences. The experiment measures and tries to reduce them.
